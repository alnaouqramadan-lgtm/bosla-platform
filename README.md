# بوصلة AI | BOSLA AI

منصة مستقلة لورش التخطيط الاستراتيجي والتشغيلي باللغة العربية (Next.js 15 / React 19 / Supabase).

## ملخص الحالة — 20 نوفمبر 2026
- المستودع: `alnaouqramadan-lgtm/bosla-platform`، والفرع المعتمد `main`.
- مشروع قاعدة البيانات المستقل: `madvrkqtducoivnaaldm` (BOSLA-AI)، منفصل تمامًا عن ENJAZ AI.
- مشروع Supabase فعّال؛ توجد **10 جداول** في `public` مع تفعيل RLS عليها و**10 ترحيلات** مسجلة حسب آخر فحص مباشر.
- إدارة المؤسسات والورش والمجموعات، التصويت، مراجعة واعتماد النماذج، الإدخال الفردي والجماعي.
- دعوة المشاركين: يضيف مدير المنصة حسابات مسجلة، ثم يفتح رابط واتساب للإرسال **اليدوي**؛ لا يوجد إرسال واتساب تلقائي.
- خمس أوراق عمل مصممة لكل مجموعة، تصدير Excel متعدد الأوراق، والطباعة عبر المتصفح وحفظ **PDF أفقي A4**. تتوافر أوراق إضافية للبيانات الأصلية والصياغات المعتمدة.
- لا تتطلب القوالب إضافة قيم وهمية في أعمدة الهدف المرتبط والكمية ودورية القياس؛ تبقى فارغة إلى حين توثيقها.
- تم اختبار بناء نسخة سابقة من التحديث الموحد في GitHub Actions (14/14)، ثم تحديث موثوقية الحفظ (18/18، typecheck وbuild)؛ يجب التحقق من نتيجة الفحوص لكل تغيير جديد قبل الدمج.

## التشغيل
1. تأكد من اختيار **مشروع بوصلة** في Supabase لا مشروع إنجاز.
2. عيّن المتغيرين على Vercel (Production وPreview وDevelopment) أو `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL=https://madvrkqtducoivnaaldm.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY=<BOSLA publishable or legacy anon key>`
3. **لا تضع مفاتيح `service_role` أو `sb_secret_` في متغيرات `NEXT_PUBLIC_`.**
4. نفّذ `npm ci` ثم `npm test` ثم `npm run typecheck` ثم `npm run build`.
5. يعمل فحص الإعدادات تلقائيًا قبل بناء Vercel. لتشغيله محليًا استخدم `npm run preflight`، وافحص `tests/ACCEPTANCE.md` قبل الاستخدام المؤسسي الواسع.

## كيفية عمل النماذج
- النماذج 1–3: تشخيص الواقع وتحليل SWOT والأهداف.
- النموذج 4: الأنشطة والبرامج والمشاريع والمستفيدون والمواعيد والمسؤولون والتكلفة.
- النموذج 5: المؤشرات وخط الأساس والمستهدفات ومصادر التحقق وآلية المتابعة.
- **تنبيه محاذاة الصفوف:** الإدخال الحالي متعدد الأسطر؛ اجعل السطر الأول في كل حقل مقابلًا للصف الأول، واترك سطرًا فارغًا إن لم توجد قيمة في الصف الثاني أو الثالث، وهكذا. تُحفظ الفراغات الداخلية عند إخراج النموذجين 4 و5.
- مخرجات المجموعات هي مدخلاتها الأصلية؛ اعتماد الميسر محفوظ في سجل منفصل. لا تفترض النماذج علاقة مباشرة بين كل هدف ونشاط ومؤشر حتى يؤكدها المستخدم.

## ما زال يحتاج تطويرًا واختبارًا
- إنشاء **صفوف إدخال منظمة** لكل نشاط ومؤشر مع معرّفات أهداف قابلة للتتبع والتحقق من الكميات ودورية القياس؛ هذا يتطلب تصميم قاعدة بيانات وصلاحيات مناسبين وليس استنتاج العلاقات من أسطر حرة.
- اعتماد شكل التقارير على أجهزة هاتف مختلفة، خاصةً النصوص الطويلة وأوراق PDF متعددة الصفحات.
- اختبار تجربة تسعة مشاركين في ثلاث مجموعات بأدوار وصلاحيات مختلفة.
- مراجعة توصيات Supabase Security Advisor، خاصةً سياسة حماية كلمات المرور المتسربة والتحقق الدوري من وظائف `SECURITY DEFINER` المصرح لها؛ لا تغيّر السياسات تلقائيًا دون فحص.
- التنبيه إلى أن حفظ PDF هنا يتم بالطباعة من المتصفح؛ لا توجد خدمة خادم مستقلة لإنشاء ملفات PDF أو DOCX.

**حدود الاستقلال:** لا تربط مستودع بوصلة أو قاعدة بياناته بمشروع `enjaz-ai`، ولا تنسخ مفاتيح إنجاز إلى Vercel بوصلة.
